The real technical picture (important for your architecture)
There are three tiers of difficulty here, not one:

Clean public JSON API (Greenhouse, Lever, Ashby, SmartRecruiters) — a single GET/POST, no browser needed. This is the easy 60-70% of companies.
Custom enterprise platforms (Workday, Phenom, iCIMS, Taleo) — no public API, and even Playwright DOM-scraping is brittle because the DOM structure varies per company.
Standard ATS embedded via client-side JS (Zapier, Close) — the ATS is one of the clean ones above, but you can't tell which without either (a) rendering the page with Playwright and inspecting network calls, or (b) a 10-second manual check in your own browser's DevTools Network tab (filter by Fetch/XHR, reload the careers page, look for a request to greenhouse.io, lever.co, ashbyhq.com, or smartrecruiters.com).
For a one-time setup of ~40 companies, honestly, option (b) — you manually checking DevTools once per company — will be faster and more reliable than me or a script guessing. It takes about as long as reading this sentence, per company.
